# طابِق | TABAQ — Streamlit MVP v1.2

**محرك مطابقة بيانات ملصقات الطاقة — بيانات وهمية وتجربة غير رسمية.**

## 1) التشغيل على Windows

افتح موجه الأوامر داخل المجلد الذي يحتوي على `app.py`:

```powershell
py -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
streamlit run app.py
```

وعلى macOS/Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
streamlit run app.py
```

يفتح التطبيق عادةً على `http://localhost:8501`.

## 2) كيف تجرّبه؟

1. اختر من القائمة **1 · تطابق كامل**، أو **2 · اختلاف في الاستهلاك**، أو **3 · حقل غير مقروء**، أو **4 · مرجع غير متاح**.
2. تظهر صورة الملصق المطابقة للحالة، وتُملأ الحقول من ملف `data/scenarios.json`؛ **هذه ليست قراءة OCR**.
3. عدّل القيم يدويًا إن أردت، ثم اضغط **إجراء المطابقة**.
4. راجع جدول الحقول. يمكن تنزيل مسودة تقرير أدلة بصيغة JSON.
5. افتح تبويب **اختبارات الجودة** لمشاهدة نتائج 60 حالة فعلية يجري تشغيلها عند فتح التبويب.

### رفع صورة شخصية

يمكن رفع ملف PNG/JPG لعرضه بجانب الحقول. **رفع الصورة لا يغيّر بيانات المقارنة ولا يثبت أن محتواها مطابق لها**. أدخل القيم أو صححها يدويًا.

### OCR الاختياري التجريبي

هذا الإصدار يتضمن زرًا لعرض **النص الخام** الذي يستخرجه Tesseract عند توافره؛ لا يتم تمريره تلقائيًا إلى محرك المطابقة، وقد يقرأ الأرقام بشكل خاطئ. لتجربته:

```bash
pip install pytesseract
```

ثم ثبّت برنامج Tesseract بشكل مستقل، مع حزمتَي اللغتين `ara` و`eng`، وأضفه لمسار التشغيل `PATH`. هذه الميزة **اختيارية تمامًا**.

## 3) اختبارات الجودة القابلة لإعادة التشغيل

```bash
python qa_runner.py
python -m unittest discover -s tests -v
```

الحالات الستون موزعة إلى 20 تطابقًا، و20 اختلافًا، و10 حالات ناقصة البيانات، و10 حالات لا تتوافر لها مراجع. لا تثبت هذه الاختبارات دقة الرؤية الحاسوبية أو التحقق على بيانات حقيقية.

## 4) بنية المشروع

```text
app.py                   واجهة Streamlit العربية
engine.py                قواعد المطابقة الأربع وحماية البيانات الناقصة
database.json            4 سجلات مكيفات اصطناعية
qa_runner.py             تشغيل اختبارات القواعد وإحصاء نجاحها
data/scenarios.json      بيانات السيناريوهات المرتبطة بالصور
data/cases_60.json       60 حالة اختبار منظمة
assets/                  أربع رسومات SVG اصطناعية لتوضيح الحالات
requirements.txt         متطلبات تشغيل الواجهة
tests/test_engine.py     12 اختبار وحدة
QA_REPORT.md             تقرير الجودة
```

## 5) حدود الاستخدام وحقوق المصادر

- البيانات والصور **اصطناعية بالكامل** ولا تمثل ملصقات أو منتجات رسمية.
- قاعدة البيانات **ليست** قاعدة بيانات الهيئة، ولا توجد واجهة API أو صلاحية تكامل مع تطبيق «تأكد».
- النتيجة لا تُثبت أصالة منتج ولا وجود مخالفة أو تزوير.
- تُفسَّر حالة «اختلاف يستدعي المراجعة» بأنها تناقض بين الحقول المُدخلة والسجل التجريبي فقط.
- لا يرسل التطبيق صورًا إلى خادم خارجي؛ ولكن تشغيله على منصة استضافة يعني أن الصور تصل إلى خادم تلك المنصة لمعالجتها محليًا هناك. في التشغيل المحلي، تبقى المعالجة على جهاز التشغيل.

**مرجع وصف تطبيق تأكد الرسمي:** https://www.saso.gov.sa/ar/takad_app/pages/default.aspx

## 6) النشر على GitHub

تتضمن الحزمة `.gitignore` وملف GitHub Actions للاختبارات داخل
`.github/workflows/tests.yml` وإعدادات واجهة Streamlit في
`.streamlit/config.toml`. للحصول على خطوات النشر، راجع [DEPLOYMENT.md](DEPLOYMENT.md).

## ملاحظة خاصة بنسخة GitHub

تستخدم النسخة المنشورة في GitHub رسومات **SVG اصطناعية** داخل `assets/` بدل صور PNG السابقة، لتوضيح الحالات الأربع. لا تمثل هذه الرسومات ملصقات رسمية أو أدلة بصرية فعلية، ولا يقوم المشروع بمطابقة محتواها بصريًا. الحالات الستون المنشورة في `data/cases_60.json` هي مجموعة اختبار بنيوية مولّدة لهذا المستودع؛ نتائجها تحتاج إلى التحقق من تشغيل GitHub Actions بعد كل تحديث.
